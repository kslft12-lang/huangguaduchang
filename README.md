# 🥒黄瓜赌场🥒 · 五个小游戏

纯静态网页，无框架、无构建、无外部依赖（不联网也能跑）。主页显示剩余金额（货币单位：**小黄瓜**），五个游戏共用同一份余额。

## 运行

```bash
# 在项目根目录起一个静态服务器（任选一种）
python -m http.server 8777 --bind 127.0.0.1
# 或 npx serve -l 8777
```

然后打开 <http://127.0.0.1:8777/>。

> 直接双击 `index.html` 也能玩，但 `file://` 下 localStorage 的隔离行为各浏览器不一致，建议用本地服务器。

## 部署

线上地址：<https://kslft12-lang.github.io/huangguaduchang/>

源仓库是 public 的 <https://github.com/kslft12-lang/huangguaduchang>，Pages 发布设置为 `main` 分支根目录。

纯静态、无构建步骤，所以**部署就是 `git push`**，推上去 GitHub 自动重新发布，几十秒生效：

```bash
git push origin main
```

不需要填构建命令或产物目录，也不需要 `.nojekyll`（仓库里没有下划线开头的文件或目录）。
唯一的约束是页面内的资源引用必须保持相对路径，否则子路径 `/huangguaduchang/` 下会拿不到文件。

## 玩法

| 页面 | 规则 | 关键赔率 |
|---|---|---|
| `index.html` | 主页：剩余金额、总局数、胜负和、累计下注、净收益 | — |
| `dice.html` | 骰子猜大小：三颗骰子物理抛掷，押 小（4–10）/ 大（11–17）/ 豹子 / 顺子 / 456 | 大小 1:1，豹子 24:1，顺子 7:1，456 30:1 |
| `versus.html` | 骰子比大小：庄家先手亮牌 → 你选继续或加注 → 开奖 | 底注 0.9 倍，加注按局势定价 |
| `blackjack.html` | 21点：六副牌牌靴，要牌 / 停牌 / 双倍，庄家 17 点停牌 | 黑杰克 3:2，平局退本 |
| `pachinko.html` | 弹珠机：投币落珠穿过铜钉阵掉进底槽，三档难度 | 见下表 |
| `tiger.html` | 老虎机：三列卷轴高速旋转，按「停止」逐列定格；三列相同即中 | 界面不显示赔率（内部约 82.5% 返还） |

余额存在浏览器 `localStorage`（键 `casino.balance`），五个页面共用，多标签页之间也会同步。
余额低于最小下注 10 时，顶栏会出现「领取救济金」。最小下注 10。

## 骰子比大小：循环大小 + 加注定价

比牌不是单纯比点数，而是三条规则绕成环：

```
111（三条一） → 压 → 456（顺子） → 通吃 → 普通点数 → 压 → 111
```

也就是 **456 是"最大点"，但它输给 111**；**111 是"最小点"，但它赢 456**。
222~666 这些豹子不特殊，按总点数参与普通比较。

流程是**庄家先手**：庄家先掷三颗骰子，但只亮出其中一颗（另外两颗扣着），你看到这一颗之后决定

- **继续** —— 按底注 50 走，赢赔 0.9 倍（返还率约 95.5%）
- **加注** —— 再压一份本金，赔率由**庄家亮出的那一颗骰子**决定（跟扣着的两颗无关）：

  | 庄家亮出 | 我方胜率 | 加注赔率 | 加注 50 赢返 |
  |---|---|---|---|
  | 1 点 | 69.4% | 不开放 | — |
  | 2 点 | 60.0% | 0.43 倍 | 71 |
  | 3 点 | 50.1% | 0.70 倍 | 85 |
  | 4 点 | 39.8% | 1.14 倍 | 107 |
  | 5 点 | 30.6% | 1.80 倍 | 140 |
  | 6 点 | 22.5% | 2.86 倍 | 193 |

庄家亮 6 点时你只有 22.5% 的胜率，但加注能赔 2.86 倍——这就是决策的张力所在。

加注必须是**按真实胜率单独定价的一注**，否则玩家只在庄家亮小牌时才加注就能稳定套利——
用 `node tools/odds-versus.js` 可以看到，如果加注固定赔 0.9 倍，那种打法每注期望 +0.14，是稳赚的。
定价后的加注整体返还率正好 95.0%。

上表的胜率和平局率由 `js/versus-rules.js` 穷举 216×216 种组合算出（庄家亮 x 之后，他的牌是 {x, u, v}，
u、v 各 36 种均匀），界面上的「赢返多少」和实际派彩共用同一个公式，看到多少就返多少：

```bash
node tools/odds-versus.js     # 打印上表，并跑一遍比牌规则的边界用例
```

## 骰子的物理动画

两个骰子游戏共用一个真 3D 骰子（`js/die.js`）：6 个面各自画好点位的立方体，
抛出后按重力下落，落地按恢复系数弹跳、每次弹跳重掷自旋，能量耗尽后补间到本次点数。
静止时保留了 16°/18° 的观察俯仰，能看到顶面和侧面。

- 动画时长约 1.8 秒，三颗骰子错开 90ms 起跳。
- 浏览器会暂停后台标签页的 `requestAnimationFrame`，所以设了 3 秒兜底定时器，
  超时直接定格到点数，避免整局卡在"掷骰中"。
- 尊重 `prefers-reduced-motion`：开启时直接显示结果，不做动画。

## 弹珠机的三档难度

三档共用**均匀对称的交错铜钉网格**（列等间距、奇数行错半格），
换难度换的是**钉阵密度**、**顶部人字檐宽度**和**翻板开口**；切换时台面上还没落底的珠子会按本金退还。

槽口上方有两根 **45° 斜翻板**：板头静止时在中线紧贴，像两扇合拢的门，然后同相位
**单向开合**（只向两侧张开、从不交叉，`(1-cos)/2` 半波相位）——珠子只有在翻板张开的
瞬间才能从中间漏进正中大奖槽（赔率最高但最难进），其余时候砸在斜板上被**切向踢力**
拨向板根、滚进两侧壁槽（赔率最低）。顶部人字檐先把落珠往两边劈，所以弹珠更容易落两边。
台面上同时最多 **10 颗珠**。

| 难度 | 铜钉 | 布局特点 | 赔率表（左→右） | 正中槽概率 | 返还率 |
|---|---|---|---|---|---|
| 简单 | 45 颗 | 均匀对称网格 + 窄人字檐，翻板开口最大 | 0.7× 0.9× 1.1× **2×** 1.1× 0.9× 0.7× | 7.7% | 86.3% |
| 普通 | 68 颗 | 均匀对称网格 + 宽人字檐 + 微离心，开口中等 | 0.6× 0.8× 1.0× **3×** 1.0× 0.8× 0.6× | 5.6% | 76.8% |
| 困难 | 87 颗 | 均匀对称密钉 + 最宽人字檐 + 离心，开口最窄 | 0.5× 0.7× 1.0× **5×** 1.0× 0.7× 0.5× | 3.3% | 68.2% |

简单档最稳（中间 2× 翻板开口最大最好进，被拨到两侧最差只输三成，单注标准差 0.34）；
困难档最凶（中间 5× 翻板开口最窄、正中坑概率只有约 1/30，被拨到两侧最差亏一半，单注标准差 0.80）。
翻板开口（`FLIPPER_AMP_ANGLE`）决定正中大奖的频率：开口越窄，正中槽越难进、返还率越低。
三档返还率都压在 **50%–90%** 区间（简单 86.3%、普通 76.8%、困难 68.2%），界面不显示返还率。

## 概率说明

- **骰子猜大小**：押大或小押中 105/216 ≈ 48.6%（开出豹子时大小通杀），押豹子 6/216 ≈ 2.8%。
  另有两个注区：顺子（任意三连 123/234/345/456，24/216 ≈ 11.11%，赔 7:1——456 也是顺子的一种，押顺子开 456 同样算中）和
  456 大奖（6/216 ≈ 2.78%，赔 30:1），两者独立判定。
- **骰子比大小**：底注返还率 95.46%；加注按庄家亮出的那一颗定价，整体返还率 95.00%
  （`node tools/odds-versus.js` 可复算）。
- **21点**：六副牌牌靴剩不到 25% 自动重洗，单局理论上限返还率约 99%（按基本策略）。
- **弹珠机**：赔率表不是拍脑袋定的。`js/pachinko-core.js` 是浏览器和 Node 共用的物理实现，
  `tools/sim-pachinko.js` 用同一个模块跑 4 万颗球统计落点分布并算出返还率：

  ```bash
  node tools/sim-pachinko.js                        # 三档难度各跑一遍
  node tools/sim-pachinko.js --level=hard --n=20000 # 单独跑某一档
  node tools/sim-pachinko.js --level=hard --pull=0.012   # 手动调参看分布怎么变
  ```

  核心里的 `prob` 数组就是实测落点概率，界面上的返还率和各槽概率都由它算出来。
  **改了铜钉布局必须重跑模拟器更新 `prob`**；只改赔率（`mults`）则界面会自动跟着变。

## 老虎机

三列卷轴、七种图形（橘子 🍊、苹果 🍎、包子 🥟、蟑螂 🪳、胡萝卜 🥕、蘑菇 🍄、最终大奖黄瓜 🥒）。
每列同时显示 **5 个图形**，中央那一行是**兑奖线**，只有停在兑奖线上的三个图形才算数（上下两行只是陪衬）。

- 下注后按「开始」扣注，结果**在按下的瞬间就已随机定死**（按各图形概率抽取），卷轴只是高速演示——滚动时三列共 15 格每帧全部换随机符号（约每秒 60 次），不可能靠看节奏预判。
- 按「停止」依次定格第一、二、三列（目标符号落在兑奖线上）；三列兑奖线相同即中奖，三根黄瓜是最终大奖。
- 界面**不显示赔率**。内部赔率表（`js/tiger.js` 的 `SYMBOLS`）：蟑螂 13 / 橘子 22 / 苹果 28 / 胡萝卜 33 / 蘑菇 45 / 包子 70 / 黄瓜 300；
  各图形出现概率不同（蟑螂最常出 30%，黄瓜最稀有 4%），三同命中率约 4.9%，加权返还率约 82.5%，与弹珠机一样压在 50%–90% 区间。
