# 🥒黄瓜赌场🥒 · 四个小游戏

纯静态网页，无框架、无构建、无外部依赖（不联网也能跑）。主页显示剩余金额，四个游戏共用一个余额。

## 运行

```bash
# 在项目根目录起一个静态服务器（任选一种）
python -m http.server 8777 --bind 127.0.0.1
# 或 npx serve -l 8777
```

然后打开 <http://127.0.0.1:8777/>。

> 直接双击 `index.html` 也能玩，但 `file://` 下 localStorage 的隔离行为各浏览器不一致，建议用本地服务器。

## 玩法

| 页面 | 规则 | 关键赔率 |
|---|---|---|
| `index.html` | 主页：剩余金额、总局数、胜负和、累计下注、净收益 | — |
| `dice.html` | 骰子猜大小：三颗骰子物理抛掷，押 小（4–10）/ 大（11–17）/ 豹子 | 大小 1:1，豹子 24:1 |
| `versus.html` | 骰子比大小：庄家先手亮牌 → 你选继续或加注 → 开奖 | 底注 0.9 倍，加注按局势定价 |
| `blackjack.html` | 21点：六副牌牌靴，要牌 / 停牌 / 双倍，庄家 17 点停牌 | 黑杰克 3:2，平局退本 |
| `pachinko.html` | 弹珠机：投币落珠穿过铜钉阵掉进底槽，三档难度 | 见下表 |

余额存在浏览器 `localStorage`（键 `casino.balance`），四个页面共用，多标签页之间也会同步。
余额低于最小下注 10 时，顶栏会出现「领取救济金」。最小下注 10。

## 骰子比大小：循环大小 + 加注定价

比牌不是单纯比点数，而是三条规则绕成环：

```
111（三条一） → 压 → 456（顺子） → 通吃 → 普通点数 → 压 → 111
```

也就是 **456 是"最大点"，但它输给 111**；**111 是"最小点"，但它赢 456**。
222~666 这些豹子不特殊，按总点数参与普通比较。

流程是**庄家先手**：庄家先掷三颗骰子，但只亮出其中一颗（另外两颗扣着），你看到这一颗之后决定

- **继续** —— 按底注 50 走，赢赔 0.9 倍（返还率约 95.5%）
- **加注** —— 再压一份本金，赔率由**庄家亮出的那一颗骰子**决定（跟扣着的两颗无关）：

  | 庄家亮出 | 我方胜率 | 加注赔率 | 加注 50 赢返 |
  |---|---|---|---|
  | 1 点 | 69.4% | 不开放 | — |
  | 2 点 | 60.0% | 0.43 倍 | 71 |
  | 3 点 | 50.1% | 0.70 倍 | 85 |
  | 4 点 | 39.8% | 1.14 倍 | 107 |
  | 5 点 | 30.6% | 1.80 倍 | 140 |
  | 6 点 | 22.5% | 2.86 倍 | 193 |

庄家亮 6 点时你只有 22.5% 的胜率，但加注能赔 2.86 倍——这就是决策的张力所在。

加注必须是**按真实胜率单独定价的一注**，否则玩家只在庄家亮小牌时才加注就能稳定套利——
用 `node tools/odds-versus.js` 可以看到，如果加注固定赔 0.9 倍，那种打法每注期望 +0.14，是稳赚的。
定价后的加注整体返还率正好 95.0%。

上表的胜率和平局率由 `js/versus-rules.js` 穷举 216×216 种组合算出（庄家亮 x 之后，他的牌是 {x, u, v}，
u、v 各 36 种均匀），界面上的「赢返多少」和实际派彩共用同一个公式，看到多少就返多少：

```bash
node tools/odds-versus.js     # 打印上表，并跑一遍比牌规则的边界用例
```

## 骰子的物理动画

两个骰子游戏共用一个真 3D 骰子（`js/die.js`）：6 个面各自画好点位的立方体，
抛出后按重力下落，落地按恢复系数弹跳、每次弹跳重掷自旋，能量耗尽后补间到本次点数。
静止时保留了 16°/18° 的观察俯仰，能看到顶面和侧面。

- 动画时长约 1.8 秒，三颗骰子错开 90ms 起跳。
- 浏览器会暂停后台标签页的 `requestAnimationFrame`，所以设了 3 秒兜底定时器，
  超时直接定格到点数，避免整局卡在"掷骰中"。
- 尊重 `prefers-reduced-motion`：开启时直接显示结果，不做动画。

## 弹珠机的三档难度

换难度会同时换**铜钉布局**和**底槽赔率表**。切换时台面上还没落底的珠子会按本金退还。

| 难度 | 铜钉 | 布局特点 | 赔率表（左→右） | 正中槽概率 | 返还率 |
|---|---|---|---|---|---|
| 简单 | 39 颗 | 稀疏规则网格，间距大 | 2× 1.5× 1× **0.5×** 1× 1.5× 2× | 44% | 95.7% |
| 普通 | 68 颗 | 标准交错网格 | 5× 2× 1× **0×** 1× 2× 5× | 43% | 96.4% |
| 困难 | 95 颗 | 12 排密钉 + 底部 V 形导流钉 | 10× 3× 1× **0×** 1× 3× 10× | 49% | 91.9% |

简单档最稳（最差只输一半，单注标准差 0.49）；困难档最凶（正中空槽概率近一半，
边缘 10 倍约 500 颗中 1 颗，单注标准差 1.24）。

## 概率说明

- **骰子猜大小**：押大或小押中 105/216 ≈ 48.6%（开出豹子时大小通杀），押豹子 6/216 ≈ 2.8%。
- **骰子比大小**：底注返还率 95.46%；加注按庄家亮出的那一颗定价，整体返还率 95.00%
  （`node tools/odds-versus.js` 可复算）。
- **21点**：六副牌牌靴剩不到 25% 自动重洗，单局理论上限返还率约 99%（按基本策略）。
- **弹珠机**：赔率表不是拍脑袋定的。`js/pachinko-core.js` 是浏览器和 Node 共用的物理实现，
  `tools/sim-pachinko.js` 用同一个模块跑 4 万颗球统计落点分布并算出返还率：

  ```bash
  node tools/sim-pachinko.js                        # 三档难度各跑一遍
  node tools/sim-pachinko.js --level=hard --n=20000 # 单独跑某一档
  node tools/sim-pachinko.js --level=hard --pull=0.012   # 手动调参看分布怎么变
  ```

  核心里的 `prob` 数组就是实测落点概率，界面上的返还率和各槽概率都由它算出来。
  **改了铜钉布局必须重跑模拟器更新 `prob`**；只改赔率（`mults`）则界面会自动跟着变。
